How it works

The same files, from both sides.

You sign in with Google and work in the apps. Agents connect to the MCP endpoint with a token you issue. Both land in the same folders, and every agent change is logged against its name.

Features

Built for sharing memory with agents.

Agents get long-term context that you can actually read and edit. You keep control over what each one sees and changes.

Projects of plain markdown

Each top-level folder is a project. Notes are ordinary .md files with folders, links between files, and attachments.

Living checklists

checklist.md renders as a nested task list. Ticking a box rewrites only that line, and concurrent appends never lose data.

Auto-compiled index

Every project has an index.md that the server rebuilds after each change. It gives agents a map of the project and can't be edited by hand.

Scoped, revocable tokens

Issue one token per agent, limited to projects like Work/* and to read or read-write. Revoking it takes effect immediately.

Activity & restore

Every agent write lands in an activity feed with a side-by-side diff. If you don't like a change, restore the previous version.

Desktop and mobile

An Electron editor for macOS and Windows and a native Expo app for iOS and Android, both signed in to the same knowledge base.

Connect an agent

Three steps, one token.

The server speaks MCP over Streamable HTTP. Any client that can send a bearer header can connect.

  1. Sign in to the app

    Open Lore LLM on desktop or mobile and sign in with Google.

  2. Create an agent

    In Settings → Agents, pick Claude or Codex, choose its projects and access level. The token is shown once and never stored by the server.

  3. Paste the setup

    Copy the generated command or config into your agent. It can now list, read and write notes in its scope.

terminal
claude mcp add --transport http lore \
  https://<your-worker>.workers.dev/mcp \
  --header "Authorization: Bearer $LORE_TOKEN"
~/.codex/config.toml
[mcp_servers.lore]
url = "https://<your-worker>.workers.dev/mcp"
http_headers = { Authorization = "Bearer $LORE_TOKEN" }
curl
curl https://<your-worker>.workers.dev/mcp \
  -H "Authorization: Bearer $LORE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call",
       "params":{"name":"list_projects","arguments":{}}}'
MCP tools

Six tools, all scoped.

Every call is confined to the agent's user and project scope, and every write is recorded in the audit log.

readlist_projects

Projects this agent is allowed to see.

readlist_files

Notes and attachments in a project or folder.

readread_file

Read a markdown note, including the project's index.md.

writewrite_file

Create a note. Overwriting needs an explicit overwrite: true.

writeappend_file

Append safely with an etag precondition, ideal for logs and checklists.

writedelete_file

Remove a note the agent has read-write access to.

Security

Isolation by default.

The trade-offs are written down in ARCHITECTURE_DECISIONS.md.

Tenant isolation in one placeEvery object key is derived from the verified token's user. Paths with .., control characters or non-markdown extensions are rejected.
Instant revocationA token only identifies the agent. Its permissions live in D1, so deleting the row cuts access at once. Tokens expire after 90 days by default.
No silent clobberingWrites don't overwrite unless asked, appends use etag preconditions, and index.md is read-only for agents.
Attachments stay with youAgents see that images and PDFs exist but can't read or write their bytes.
Self-host

Runs on the free tier.

The backend fits Cloudflare's free plan: 100k requests a day, and every request is I/O-bound apart from a single JWT verification. Bring your own Cognito user pool and deploy with Wrangler.
